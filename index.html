The Favicon Debugging Checklist

Your site icon is missing, blurry, or stuck on some random letter — here's the symptom → cause → fix for every favicon failure that shows up in real projects. Each linked tool runs 100% in your browser; no account, nothing uploaded.

1 · "My favicon isn't showing up at all"

Ninety percent of the time it's one of six boring causes, not a browser bug. Work through the list before touching code:

  • CHECK The file is named favicon.ico but lives anywhere but the site root — browsers only look at /favicon.ico by default → all 10 causes, ranked by frequency
  • CHECK You deployed a new icon but every device shows the old one → that's cache, not your code. Hard-reload, then bust with ?v=2 on the href
  • CHECK The <link rel="icon"> tag points to a 404 — open the URL directly in a tab and see what actually comes back
  • CHECK You're testing on localhost and expecting the production icon → local dev servers and browser profiles cache aggressively
  • CHECK Unsure what your site is actually serving right now? Run it through the Favicon Checker — it fetches the live page, reads the declared icons, and reports what each one resolves to
  • CHECK Not sure what a favicon technically is (ico vs png vs manifest)? Start with what a favicon actually is

2 · "It renders, but it's blurry / mushy on retina screens"

A single 16×16 icon upscaled by the browser will always look like wet cardboard. You need one file per render size:

  • CHECK Ship the full ladder, not one file: 16×16 (browser tab), 32×32 (taskbar, retina tabs), 192×192 (Android home screen), 512×512 (PWA splash & store listings)
  • CHECK Exporting from a small source image and upscaling? That's the blur. Start from something ≥512×512 or vector → why favicons go blurry
  • CHECK Not sure which sizes the major platforms actually read in 2026? The favicon size guide maps every size to where it's used
  • CHECK A 32×32 icon that was scaled down from 16×16 artwork will alias badly — design at large size, derive downward

3 · "iOS ignores my favicon"

Correct — it does, on purpose. Safari on iOS/iPadOS never reads favicon.ico; it wants apple-touch-icon:

  • CHECK Missing <link rel="apple-touch-icon"> at 180×180 → add it; the apple-touch-icon guide covers sizing, rounding, and the black-background pitfall
  • CHECK Icon has transparency → iOS composites it onto black. Export on your brand background
  • CHECK Safari on macOS also supports a mask-icon / dark-mode variant — worth shipping if your audience is Apple-heavy

One habit that prevents most of the above: treat favicon files as build output, not design artifacts. Keep one master ≥512×512 source (or SVG), and regenerate the whole size set on every brand change. Hand-maintained icon folders are where stale sizes and 404s come from.
